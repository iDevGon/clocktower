# 게임플레이 안정성 및 UX 개선 설계

## 목표

에디션별 활성 직업 범위와 악마 블러프를 일치시키고, 사망·재접속·강퇴·iOS 햅틱 문제를 원인 기반으로 수정한다. 동시에 이야기꾼이 플레이어의 투표 기록 공개와 타이머를 세밀하게 제어할 수 있게 하고, 사전·좌석·투표·밤 진행·야간 피드백 UI를 게임 정보 노출 없이 명확하게 개선한다.

## 범위와 작업군

전체 요청을 다음 네 작업군으로 나눈다. 각 작업군은 독립적으로 테스트할 수 있지만, 활성 직업과 게임 설정은 공유 모델을 통해 연결한다.

1. 공통 규칙·설정: 요구사항 1, 5, 6, 9, 10.
2. 안정성·플랫폼·세션: 요구사항 2, 3, 8.
3. 플레이어 투표·좌석·야간 UX: 요구사항 4, 7, 11, 12, 13.
4. 이야기꾼 야간 피드백 모달: 요구사항 14.

관련 없는 리팩터링, 신규 역할, 게임 규칙 변경, 데이터베이스 도입은 범위에서 제외한다.

## 핵심 설계 원칙

- 현재 등장 가능한 일반 직업의 기준은 `현재 에디션 직업 - 제외 직업 + 명시적으로 추가한 다른 에디션 직업`이다.
- 활성 직업 계산은 공유 패키지의 단일 함수가 담당하며 서버, 플레이어 앱, 이야기꾼 앱, 공유 사전이 같은 결과를 사용한다.
- 서버는 게임 설정과 플레이어 세션의 권위 있는 상태를 유지한다. 클라이언트는 서버 응답으로 영속 상태를 복원하고 일시적 연출 상태는 재생하지 않는다.
- 버그 수정은 재현 테스트 또는 실패 경로를 먼저 확인한 뒤 최소 변경으로 수행한다.
- 야간 피드백 추천은 이야기꾼을 보조할 뿐 선택을 강제하지 않는다. 거짓 정보를 제공해야 하는 상태에서는 실제값 추천을 노출하지 않는다.

## 1. 공통 활성 직업과 악마 블러프

### 활성 직업 계산

공유 패키지에 다음 입력을 받는 활성 직업 계산 경계를 둔다.

- `editionId`: 현재 플레이 중인 에디션.
- `excludedRoleIds`: 현재 에디션에서 제외한 직업 ID.
- `additionalRoleIds`: 다른 에디션에서 명시적으로 추가한 직업 ID.

결과는 현재 에디션의 일반 직업에서 제외 목록을 뺀 뒤 추가 목록을 합친 중복 없는 직업 목록이다. 여행자는 에디션별 별도 목록을 유지하며 일반 직업 활성 범위에 섞지 않는다.

### 악마 블러프 후보

악마 블러프 후보는 활성 직업 중 다음 조건을 모두 만족하는 직업이다.

- 선한 진영인 마을주민 또는 외지인이다.
- 실제 플레이어에게 배정되지 않았다.
- 주정뱅이와 미치광이처럼 기존 규칙상 랜덤 블러프에서 제외하는 특수 직업이 아니다.

현재 에디션 소속이더라도 제외된 직업은 블러프 후보가 아니다. 반대로 다른 에디션 소속이더라도 추가 목록에 포함되면 블러프 후보가 된다. 이야기꾼이 사전 선택한 블러프도 같은 후보 검증을 거치며, 유효하지 않은 선택은 유효한 랜덤 후보로 보충한다.

역할 자동 배분 시 선택한 블러프를 실제 역할 배분에서 제외하는 기존 동작은 유지한다.

## 2. 사전과 기본 진영 구성

### 직업 및 진행순서 필터

플레이어 앱과 이야기꾼 앱은 `DictionaryModal`에 동일한 활성 직업 ID를 전달한다. 직업 탭과 진행순서 탭은 다음 원칙을 따른다.

- 현재 에디션의 제외되지 않은 직업을 표시한다.
- 다른 에디션에서 추가된 직업을 표시한다.
- 제외된 직업은 직업 목록과 밤 진행 예시에서 모두 숨긴다.
- 첫날 밤과 이후 밤 순서는 각 직업의 원래 에디션 순서를 보존해 합성한다.
- 실제 배정 여부와 무관하게 현재 셋업에서 등장 가능한 직업을 예시로 설명한다.

### 인원 구성 탭

사전에 `인원 구성` 탭을 추가한다. 현재 게임의 여행자를 제외한 일반 플레이어 수를 기준으로 기본 역할 분배표의 마을주민·외지인·하수인·악마 수를 표시한다.

남작, 대부 등 특정 직업의 셋업 효과와 이야기꾼의 수동 역할 변경은 반영하지 않는다. 이 화면은 일반적인 기본 등장 수를 설명하는 참고 정보다. 지원 범위를 벗어난 인원이라면 해당 인원에 대한 기본 구성이 없음을 안내한다.

## 3. 게임 설정과 타이머 입력

### 투표 기록 공개 설정

`GameSettings`에 `showVoteHistory: boolean`을 추가하며 기본값은 `true`다.

이야기꾼이 로비 또는 게임 설정에서 값을 변경하면 기존 설정 이벤트 경로를 통해 서버에 저장되고 접속 중인 모든 플레이어에게 즉시 동기화된다. 플레이어 좌석 화면의 이전 투표 기록 영역은 이 값이 `true`일 때만 렌더링한다. 값이 `false`로 바뀌면 열려 있던 기록 선택 상태도 해제한다.

### 상세 시간 입력

기존 프리셋 슬라이더는 유지하고 각 타이머에 분·초 숫자 입력을 함께 제공한다.

- 슬라이더 변경은 입력값을 즉시 갱신한다.
- 입력값 변경은 같은 초 단위 `GameSettings` 값을 갱신한다.
- 초 입력은 0~59 범위로 정규화하고 분 입력과 합산한다.
- `0분 0초`는 기존의 0초 설정과 동일하게 무제한을 뜻한다.
- 음수, 숫자가 아닌 값, 유한하지 않은 값은 설정에 반영하지 않는다.
- 입력 중에는 로비의 스크롤/드래그 제스처와 충돌하지 않게 기존 상호작용 시작·종료 콜백을 유지한다.

## 4. 사망과 재접속 안정성

현재 보고 범위는 iOS와 Android 모두이며 사망 방식은 밤 사망, 처형, 처단자 등으로 한정되지 않는다. 따라서 특정 사망 효과를 추측해 수정하지 않고 공통 상태 전이와 오버레이 조합을 먼저 조사한다.

### 조사와 수정 경계

- 각 사망 이벤트가 갱신하는 `isAlive`, `justDied`, `deathReason`, 실행/밤 사망 알림과 전체화면 오버레이 상태를 추적한다.
- 동시에 참이 될 수 있는 오버레이 조합을 재현 테스트로 만든다.
- 오버레이 컴포넌트가 불완전한 대상 데이터 또는 해제된 역할을 참조하지 않게 한다.
- 한 사망 전이에 대한 전면 사망 연출은 한 번만 표시한다.

### 재접속 복원

재접속 성공 시 서버 응답의 역할, 생존 여부, 현재 페이즈, 낮 서브페이즈, 밤 순서, 지명, 처형 후보, 유령표 사용 여부, 게임 설정을 한 번의 상태 갱신으로 복원한다.

`justDied`, 사망·처형·특수 역할 오버레이, 일시적 선택값처럼 이미 지나간 연출 상태는 재접속으로 복원하거나 재생하지 않는다. 재접속 대상이 서버에 없다는 확정 응답을 받으면 오래된 플레이어 ID를 제거하고 입장 화면으로 돌아가며 자동 재접속 반복을 중단한다. 일시적 네트워크 실패는 세션 삭제와 구분한다.

## 5. iOS 햅틱

iOS에서 React Native `Vibration` 패턴에 의존하는 사용자 피드백을 Expo 네이티브 햅틱 API 기반 공통 유틸로 통합한다. 알림, 선택, 성공, 경고처럼 현재 사용 목적에 맞는 강도를 매핑한다.

- iOS는 햅틱 API를 사용한다.
- Android는 기존 진동 패턴을 유지한다.
- 웹과 지원하지 않는 환경에서는 오류 없이 무시한다.
- 비동기 햅틱 호출 실패가 게임 이벤트 처리나 화면 렌더링을 중단하지 않게 한다.
- 기존 개별 컴포넌트와 소켓 리스너의 직접 `Vibration` 호출은 공통 유틸을 사용하도록 바꾼다.

## 6. 접속하지 않은 플레이어 강퇴

강퇴 처리는 대상 소켓 존재 여부와 분리한다.

1. 서버 게임 상태에서 대상 플레이어 존재를 확인한다.
2. 게임 상태와 재접속 가능한 플레이어 ID에서 대상을 제거한다.
3. 대상 소켓이 연결되어 있으면 강퇴 이벤트를 보낸 뒤 방에서 제거한다.
4. 나머지 플레이어와 이야기꾼에게 퇴장 및 최신 게임 상태를 보낸다.
5. 연결되지 않은 대상도 동일한 성공 응답을 반환한다.

강퇴된 플레이어가 보관 중인 이전 ID로 재접속하면 존재하지 않는 세션이라는 확정 실패를 받고 로컬 세션을 정리한다. 새 플레이어로 다시 참가하는 정책은 기존 참가/승인 흐름을 유지한다.

## 7. 투표와 처단자 오버레이

투표 시계가 진행 중일 때 처단자 선언 이벤트와 서버 판정은 즉시 처리한다. 다만 투표 조작을 가리는 전체화면 오버레이는 플레이어 앱의 연출 대기열에 저장한다.

- 투표 시계 또는 투표 입력이 활성화된 동안 전면 처단자 연출을 열지 않는다.
- 투표 종료/결과 수신 후 대기 중인 처단자 연출을 한 번 표시한다.
- 여러 전면 연출이 겹치면 이벤트 순서를 보존한다.
- 지연 중에도 사망 여부와 좌석 표시는 서버 상태에 맞게 갱신한다.

## 8. 플레이어 좌석과 밤 화면

### 메모 모달

좌석 메모 모달의 직업 검색 입력에 설정된 자동 포커스를 제거한다. 사용자가 입력을 직접 누르기 전에는 키보드가 열리지 않는다.

### 밤 진행 정보 제거

플레이어 밤 화면에서 전체 밤 진행 노드, 현재 진행 역할, 전체 순서 추정에 사용할 수 있는 시각 정보를 제거한다. 서버가 해당 플레이어에게 직접 보낸 `night:wakeUp`을 기준으로 본인 행동 UI만 표시한다. 일반적인 밤 안내와 대기 문구는 역할 진행 여부를 드러내지 않는 정적인 내용으로 유지한다.

### 유령표 상태와 투표 문구

사망 플레이어의 좌석 상태를 다음 두 가지로 명시한다.

- `유령표 보유`: 아직 사망 후 1회 투표권이 남아 있음.
- `유령표 사용`: 사망 후 투표권을 이미 사용함.

두 상태는 서로 다른 색상과 아이콘을 사용하고 접근성 라벨에도 같은 의미를 담는다. 유령표를 사용한 본인의 투표 버튼은 비활성화하면서 문구를 `유령표를 이미 사용했습니다`로 바꾼다.

## 9. 이야기꾼 야간 피드백 모달

기존 밤 순서 위의 단순 중앙 패널을 독립 모달로 바꾼다. 비주얼 컴패니언에서 승인한 방향은 다음과 같다.

- 각진 2~3px 모서리와 팀 색상 테두리를 사용한다.
- 영문 키커 없이 역할명과 대상/진행 수를 한글로 표시한다.
- 역할 능력, 판정 근거, 추천 피드백, 선택 버튼, 전송 버튼 순서로 배치한다.
- 숫자·예/아니오·역할·플레이어 선택 버튼은 큰 터치 영역과 높은 대비를 사용한다.
- 추천값은 금빛 그라데이션, 글로우, `추천` 라벨로 명확히 구분한다.
- 미전송 상태에서도 모달을 접고 밤 순서나 판정 보조 UI를 확인할 수 있으며 다시 열면 현재 선택을 유지한다.

### 추천 피드백 정합성

추천은 현재 게임 상태에서 결정적으로 계산할 수 있을 때만 제공한다. 최소 점검 대상은 초공감자, 요리사, 점쟁이, 장의사, 까마귀지기, 곡예사와 현재 `NIGHT_FEEDBACK`에서 자동 근거가 있는 역할이다.

- 정상 작동 중이면 계산된 실제값에 추천 강조를 적용한다.
- 취함, 중독 또는 능력 오작동 상태이면 실제값 추천을 숨기고 `가짜 정보 제공 필요` 경고를 표시한다.
- 추천 버튼 외의 값을 수동으로 선택하고 전송할 수 있다.
- 화면에서 강조한 값, 선택한 값, 서버로 전송한 payload가 일치해야 한다.
- 여러 플레이어가 같은 역할 피드백 대상이면 대상별 추천과 전송 완료 상태를 독립적으로 관리한다.

## 오류 처리

- 서버 설정과 역할 배분 요청은 기존 콜백의 성공 응답을 받은 뒤 UI 완료 상태를 갱신한다.
- 입력값 검증 실패는 마지막 유효값을 유지한다.
- 재접속 실패는 서버가 세션 부재를 확정한 경우와 네트워크 시간 초과를 구분한다.
- 햅틱 실패는 사용자 흐름을 막지 않는다.
- 피드백 전송 실패 시 모달과 현재 선택을 유지하고 재시도할 수 있게 한다.

## 테스트 전략과 완료 조건

### 공유 패키지

- 현재 에디션, 제외 목록, 추가 목록의 조합으로 활성 직업이 정확히 계산된다.
- 기본 역할 분배표를 공개 함수로 조회할 수 있고 지원 범위 밖 인원을 처리한다.
- 사전 필터와 밤 진행순서가 동일한 활성 직업 목록을 사용한다.

### 서버 단위 및 E2E

- 랜덤 및 사전 선택 블러프에 제외 직업이 들어가지 않는다.
- 다른 에디션에서 추가한 미배정 선한 직업은 블러프 후보가 된다.
- 오프라인 플레이어 강퇴 뒤 상태에서 제거되고 이전 ID 재접속이 실패한다.
- `showVoteHistory`와 상세 타이머 값이 저장되고 모든 클라이언트에 동기화된다.
- 사망 종류별 재접속 응답이 완전하며 일시적 오버레이 상태를 요구하지 않는다.

### 플레이어 앱

- 사망 이벤트 조합에서 예외 없이 한 개의 전면 연출만 표시한다.
- 재접속 성공/세션 부재/네트워크 실패를 구분한다.
- 투표 중 처단자 오버레이는 지연되고 투표 종료 후 한 번 표시된다.
- 야간 진행 노드가 렌더링되지 않는다.
- 투표 기록 설정, 유령표 상태, 유령표 사용 완료 문구, 메모 모달 포커스를 검증한다.
- iOS 햅틱 유틸이 올바른 네이티브 API를 호출하고 실패를 흡수한다.

### 이야기꾼 앱과 공유 UI

- 기존 프리셋과 분·초 입력이 같은 초 단위 설정을 갱신한다.
- 사전의 직업·진행순서·인원 구성 탭이 현재 셋업과 일반 플레이어 수를 사용한다.
- 피드백 모달의 추천값, 오작동 시 추천 숨김, 전송 payload, 다중 대상 진행을 역할별로 검증한다.
- 큰 버튼, 접근성 라벨, 모달 닫기/접기 동작을 검증한다.

### 최종 검증

관련 테스트의 실패를 먼저 확인하고 최소 구현으로 통과시킨다. 이후 `pnpm test`, `pnpm test:e2e`, `pnpm typecheck`, `pnpm lint`, `pnpm build`를 새로 실행한다. 각 요구사항에 대응하는 테스트 또는 수동 재현 결과와 실제 diff를 함께 확인한 경우에만 완료로 판단한다.
