# 도박사 추측 제출·검토 설계

## 배경

현재 도박사는 `NIGHT_ACTIONS`에서 `passive`로 정의되어 있다. 플레이어 앱은 밤 차례에 선택 UI 대신 “이야기꾼 앱에서 플레이어와 캐릭터 추측을 기록하세요”라는 안내만 보여 준다. 이야기꾼 앱에는 대상과 역할을 직접 고르는 판정 패널이 있지만, 플레이어의 앱 내 제출 경로가 없어 실제 게임에서 채팅으로 선언을 전달해야 한다.

## 목표

- 도박사가 플레이어 앱에서 플레이어 1명과 역할 1개를 비공개로 제출한다.
- 이야기꾼 앱은 제출값을 기본 선택값으로 보여 준다.
- 이야기꾼은 대상과 역할을 수정한 뒤 승인하거나 제출을 반려할 수 있다.
- 승인 전에는 정답 판정이나 사망 처리를 하지 않는다.
- 재접속과 바리스타의 능력 2회 발동에서도 각 제출의 상태가 섞이지 않는다.

## 비목표

- 도박사의 정답 여부를 플레이어에게 공개하지 않는다.
- 채팅 메시지를 구조화된 도박사 제출로 변환하지 않는다.
- 다른 수동 BMR 역할의 제출 흐름을 함께 변경하지 않는다.
- 이야기꾼의 반려 사유 입력 기능은 추가하지 않는다.

## 선택한 접근

서버가 승인 대기 중인 도박사 제출을 명시적으로 보관하는 전용 흐름을 사용한다. 소켓 이벤트만 전달하는 방식은 재접속 시 제출이 사라지고, 범용 `night:action` 확장은 일반 대상 선택과 승인 대기 상태를 한 계약에 섞으므로 사용하지 않는다.

## 사용자 흐름

### 플레이어 앱

1. 서버가 도박사의 밤 차례를 알리면 전용 도박사 추측 화면을 표시한다.
2. 플레이어 목록에서 1명, 현재 게임에 등장 가능한 역할 목록에서 1개를 선택한다.
3. 제출하면 입력을 잠그고 `이야기꾼 확인 대기 중` 상태를 표시한다.
4. 승인되면 `행동 완료` 상태를 유지한다. 정답 여부나 사망 여부는 표시하지 않는다.
5. 반려되면 선택 화면을 다시 열고 `이야기꾼이 제출을 반려했습니다. 다시 선택하세요.`를 표시한다.

대상은 기존 이야기꾼 도박사 패널과 동일하게 생존 여부, 여행자 여부, 자기 자신 여부와 관계없이 전체 플레이어를 허용한다. 역할 목록은 설정된 에디션에서 제외 역할을 빼고 추가 역할과 현재 참가 중인 여행자 역할을 포함한다.

### 이야기꾼 앱

1. 활성 밤 역할이 도박사이고 승인 대기 제출이 있으면 기존 도박사 판정 패널의 대상과 역할을 제출값으로 초기화한다.
2. 이야기꾼은 두 값을 자유롭게 수정할 수 있다.
3. `승인`은 현재 선택된 최종값으로 판정한다.
4. `반려`는 제출을 폐기하고 해당 플레이어에게 재제출을 요청한다.
5. 승인이나 반려 요청을 처리하는 동안 버튼을 중복 누를 수 없게 한다.

승인 대기 제출이 없는 동안에는 `플레이어 제출 대기 중`을 표시한다. 기존 수동 판정 경로는 제거하여 승인되지 않은 임의 값으로 먼저 판정되는 경로를 만들지 않는다.

## 서버 상태와 이벤트

서버는 한 번에 활성화된 밤 차례에 대응하는 다음 정보를 보관한다.

```ts
interface PendingGamblerGuess {
  requestId: string;
  gamblerId: string;
  targetPlayerId: string;
  guessedRoleId: string;
}
```

필요한 이벤트 계약은 다음 책임으로 나눈다.

- 플레이어 → 서버: 대상과 추측 역할 제출
- 서버 → 이야기꾼: 승인 대기 제출 전달
- 이야기꾼 → 서버: 요청 ID, 승인/반려 결정, 승인 시 최종 대상과 역할 전달
- 서버 → 해당 플레이어: 승인 또는 반려 결과 전달

서버는 소켓에서 플레이어 ID를 확인하고, 게임이 밤이며 현재 활성 역할과 플레이어의 효과적 역할이 도박사인지 검증한다. 대상 플레이어와 추측 역할도 현재 게임 데이터에 존재해야 한다. 클라이언트가 임의의 도박사 ID를 제출하도록 허용하지 않는다.

`requestId`가 현재 승인 대기 요청과 일치할 때만 승인·반려한다. 이미 처리된 요청의 늦은 응답은 무시하여 다음 제출에 적용되지 않게 한다.

승인 대기 상태는 게임 재시작, 리셋, 밤 역할 변경 시 정리한다. 도박사 플레이어의 재접속 응답에는 본인의 승인 대기 여부를 포함하고, 이야기꾼 재접속 상태에는 전체 승인 대기 제출을 포함한다.

## 판정과 밤 순서

승인 시 서버는 이야기꾼이 최종 선택한 대상과 역할로 기존 도박사 판정 로직을 호출한다.

- 맑은 정신이며 추측이 맞음: 사망 없음
- 맑은 정신이며 추측이 틀림: 도박사를 야간 사망 대기열에 추가
- 취함·중독 등 능력 오작동 상태: 사망 없이 처리 완료

어느 경우에도 플레이어에게 정답 여부를 보내지 않는다. 승인 처리가 성공하면 현재 요청을 제거하고 다음 밤 기상 대상을 진행한다. 바리스타로 같은 플레이어가 두 번 행동하면 첫 승인 후 두 번째 기상 이벤트가 전달되고, 새 `requestId`로 별도 제출을 받는다.

반려 시에는 요청만 제거한다. 밤 기상 대기열을 진행하지 않고, 현재 플레이어가 같은 차례에서 다시 제출할 수 있게 한다.

## 클라이언트 상태

플레이어 스토어는 도박사 제출 상태를 `idle | pending | approved | rejected`로 구분하고 현재 요청 ID를 보관한다. 새 밤 역할 차례, 게임 리셋, 승인 완료 시 불필요한 이전 오류 문구를 정리한다.

이야기꾼 스토어는 서버 상태의 승인 대기 제출을 단일 출처로 사용한다. 패널의 편집용 대상·역할 상태는 새 `requestId`가 들어올 때만 제출값으로 초기화하여, 관련 없는 재렌더가 이야기꾼의 수정 내용을 되돌리지 않게 한다.

## 오류 처리

- 플레이어 제출 검증 실패: 입력 화면을 유지하고 한국어 오류를 표시한다.
- 승인 시 대상이나 역할이 사라짐: 판정하지 않고 이야기꾼에게 오류를 표시하며 요청을 유지한다.
- 승인·반려 중 연결 끊김: 서버의 현재 승인 대기 상태를 재접속 후 다시 복원한다.
- 중복 제출: 동일 요청이 대기 중이면 새 요청을 만들지 않는다.

## 테스트 기준

### 공유 타입·서버

- 플레이어 본인만 자신의 도박사 추측을 제출할 수 있다.
- 밤/활성 역할/효과적 역할/대상/역할 검증이 동작한다.
- 제출만으로 판정이나 사망이 발생하지 않는다.
- 이야기꾼 승인 시 수정된 값으로 판정한다.
- 반려 시 판정과 밤 순서 진행 없이 재제출할 수 있다.
- 취함·중독 상태의 승인은 사망 없이 완료된다.
- 오래된 요청 ID의 응답은 새 제출에 영향을 주지 않는다.
- 바리스타 2회 발동은 두 요청과 두 승인을 순서대로 처리한다.
- 플레이어와 이야기꾼 재접속 시 대기 상태가 복원된다.

### 플레이어 앱

- 도박사 차례에 대상·역할 선택 UI가 표시된다.
- 둘 중 하나라도 선택하지 않으면 제출할 수 없다.
- 제출 후 대기 상태, 반려 후 재입력 상태, 승인 후 완료 상태를 표시한다.
- 정답 여부는 어떤 상태에서도 렌더하지 않는다.

### 이야기꾼 앱

- 제출값이 대상·역할 기본값으로 설정된다.
- 이야기꾼이 수정한 값이 승인 payload에 사용된다.
- 승인·반려 버튼과 처리 중 중복 방지가 동작한다.
- 새 요청이 아닌 렌더에서는 수정 중인 값을 덮어쓰지 않는다.

### 회귀 검증

- 전체 단위 테스트와 서버 E2E를 실행한다.
- shared, server, player, storyteller 타입 검사를 실행한다.
- Biome 검사와 저장소 빌드를 실행한다.
