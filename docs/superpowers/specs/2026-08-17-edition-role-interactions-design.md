# 에디션별 역할·상호작용·이야기꾼 컨트롤 검증 설계

## 목표

Trouble Brewing, Sects & Violets, Bad Moon Rising와 각 에디션의 여행자 역할이 원작 규칙에 맞게 동작하는지 점검하고, 확인된 서버 판정·역할 상호작용·이야기꾼 컨트롤 결함을 별도 브랜치에서 테스트 우선으로 수정한다.

## 현재 상태와 확인된 문제

현재 구현은 공유 역할 정의(`packages/shared/src/roles.ts`), 서버 상태/판정(`apps/server/src/game.ts`와 소켓 핸들러), 이야기꾼 앱의 밤 진행·수동 판정 UI로 나뉘어 있다. 기존 단위 테스트는 통과하지만, 공식 BMR 밤 시트와 코드를 대조했을 때 다음 차이가 확인되었다.

- BMR 두 번째 밤 이후 순서에 첫 밤 전용 여행자 `apprentice`가 남아 있다.
- Vortox가 첫 낮에 처형되지 않았을 때 낮 종료 시 승리 판정이 실행되지 않는다.
- 중독된 Scarlet Woman이 악마 사망 시 악마로 승계할 수 있다.
- Barber 역할 교환과 Pit Hag 역할 변경 뒤 플레이어의 명시적 `alignment`가 새 역할과 불일치할 수 있다.
- Pit Hag가 Demon을 만드는 경우 원작의 해당 밤 돌연사 판정과 이야기꾼 조작 경로가 없다.
- BMR 자동 사망 판정에서 역할별 보호·중독·취함 상호작용이 서버와 이야기꾼 UI 사이에서 일관되지 않다.
- Butler 제한이나 Beggar 토큰 검증에 실패해도 투표권/토큰이 먼저 소비될 수 있다.
- 수동 BMR 컨트롤 일부가 서버 성공 응답과 완료 표시의 경계를 완전히 보장하지 않는다.

원작 비교 기준은 공식 BMR 역할/밤 시트와 공식 능력 규칙 문서로 삼는다. 밤 시트의 실제 순서는 참고용이며, 역할 능력의 효과·보호·역할 변경 규칙은 해당 역할의 능력 설명과 공식 능력 규칙을 우선한다.

## 범위

포함:

1. 세 기본 에디션의 역할 목록, 여행자 목록, 첫 밤/이후 밤 순서, `NIGHT_ACTIONS`와 `NIGHT_FEEDBACK`의 정합성.
2. 역할 변경·승계·사망 트리거·보호·중독/취함·진영 변경·승리 조건처럼 여러 역할에 영향을 주는 공유 상태 판정.
3. 이야기꾼 앱에서 역할 선택, 밤 진행, 수동 사망/상태/피드백/상호작용 컨트롤이 서버의 성공·실패 결과와 일치하는지.
4. 위 결함을 재현하는 공유 단위 테스트, 서버 E2E 테스트, 필요한 이야기꾼 소스/상호작용 테스트.

제외:

- 원작에 없는 신규 역할이나 하우스룰 추가.
- 시각적 리디자인, 저장소/DB 도입, 게임 엔진 전체 재작성.
- 재현 근거가 없는 추측성 규칙 변경. 그런 항목은 수정하지 않고 별도 보고한다.

## 설계 원칙

- 서버 `GameManager`를 판정의 권위로 유지한다. UI는 서버 성공 콜백을 받은 뒤에만 로컬 완료 상태를 갱신한다.
- 결함마다 먼저 최소 실패 테스트를 추가하고, 한 가지 원인만 수정한 뒤 해당 테스트와 관련 회귀 테스트를 실행한다.
- 역할 변경 시 역할에서 파생되는 진영과 일회성 능력 상태를 새 캐릭터 기준으로 재설정하되, 독립적인 상태 효과(예: 현재 중독)는 원작 규칙에 따라 보존한다.
- 에디션 기본 순서와 크로스 에디션 추가 역할을 구분한다. 추가 역할 때문에 기본 에디션의 밤 순서가 자동으로 다른 에디션으로 바뀌지 않도록 한다.
- Storyteller가 원작상 임의로 판단해야 하는 효과는 자동 판정으로 가장하지 않고 명시적 컨트롤과 확인 상태를 제공한다.

## 구현 단위

### 1. 공유 규칙/순서 정합성

`packages/shared/src/roles.ts`와 역할 테스트를 수정한다. 공식 순서와 비교해 BMR 이후 밤의 `apprentice` 노출을 제거하고, 모든 에디션의 역할·여행자·밤 행동 정의가 현재 스크립트에 맞는지 검증한다. 필요하면 설정의 `setupEditionId`를 기준으로 순서를 선택하고, 추가 역할은 별도 활성 역할로만 합친다.

### 2. 서버 상호작용 판정

`apps/server/src/game.ts`를 중심으로 다음 상태 전이를 테스트한다.

- Vortox 첫 낮 무처형 승리.
- Scarlet Woman의 sober/healthy 조건.
- Barber/Pit Hag 역할 변경 후 alignment와 일회성 상태.
- Pit Hag가 Demon을 만들 때 필요한 돌연사 대기/확정 컨트롤.
- Pukka, Shabaloth, Po, Zombuul, Assassin, Godfather, Gossip, Moonchild의 사망 결과와 BMR 보호 상호작용.
- 투표 실패 시 Beggar 토큰·유령 투표권 보존.

기존 소켓 이벤트 명명 규칙을 유지하고, 새 이벤트가 필요할 때만 `packages/shared/src/events.ts`, 서버 핸들러, 이야기꾼 액션 훅을 함께 변경한다.

### 3. 이야기꾼 컨트롤

`apps/storyteller/app/game/grimoire.tsx`, `NightPanel.tsx`, `NightActionLog.tsx`, `useGameActions.ts`를 검토한다. 특수 판정 컨트롤은 다음 순서를 따른다.

1. 대상/역할 선택.
2. 서버 이벤트 전송.
3. 성공 응답 수신.
4. 그때만 완료 표시, 로그 기록, 모달 닫기.

실패하면 선택 상태와 모달을 유지하고 서버 오류를 이야기꾼이 확인할 수 있게 한다. 자동으로 처리되는 역할과 수동으로 처리하는 역할이 같은 대상을 이중 처리하지 않도록 한다.

## 검증 계획

- 공유 패키지: 역할 개수, 에디션별 순서, 액션/피드백 정의 테스트.
- 서버 단위 테스트: 순수 상태 전이와 승리 조건.
- 서버 E2E: 실제 Socket.io 이벤트를 통한 밤 행동, 역할 변경, 투표, 이야기꾼 컨트롤.
- 앱 소스/컴포넌트 테스트: 성공 콜백 이후 완료 처리, 에디션 순서/후보 역할, 컨트롤 누락.
- 최종 게이트: `pnpm test`, `pnpm test:e2e`, `pnpm typecheck`, `pnpm lint`, `pnpm build`.

완료는 테스트가 통과했다는 사실만으로 판단하지 않고, 위 범위의 각 결함에 대응하는 테스트와 실제 변경 diff를 함께 확인한 뒤 판단한다.
