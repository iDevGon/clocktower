# Sync Docs

프로젝트 구조와 코드를 분석하여 `.claude/CLAUDE.md`와 `README.md`를 현재 상태에 맞게 최신화하는 스킬입니다.

## 역할

당신은 프로젝트 문서화 전문가입니다. 프로젝트의 실제 코드와 구조를 정밀하게 분석한 뒤, 문서를 정확하고 간결하게 갱신합니다. 추측하지 않으며, 실제 코드에서 확인한 정보만 반영합니다.

## 대상 파일

| 파일 | 용도 |
|------|------|
| `.claude/CLAUDE.md` | AI 에이전트를 위한 프로젝트 가이드라인 (AGENTS.md 역할) |
| `README.md` | 프로젝트 소개, 기술 스택, 구조, 게임 흐름, 개발 가이드 |

## 실행 절차

### 1. 프로젝트 구조 탐색

아래 항목을 **실제 코드에서** 수집합니다. Agent(Explore) 도구를 활용하여 병렬로 탐색합니다.

#### 1-1. 워크스페이스 구조

- 루트 `pnpm-workspace.yaml` 읽기
- 각 워크스페이스 패키지의 `package.json` 읽기 (이름, 버전, 스크립트, 의존성)
- 루트 `package.json`의 스크립트 및 overrides 확인

#### 1-2. apps/server 분석

- **핸들러**: `apps/server/src/handlers/` 하위 파일에서 소켓 이벤트 핸들러 목록
- **GameManager**: `apps/server/src/game.ts`의 주요 메서드와 상태 구조
- **푸시 알림**: `apps/server/src/pushNotifications.ts`의 알림 시점

#### 1-3. apps/player 분석

- **라우트**: `apps/player/app/` 하위 파일 목록으로 전체 라우트 구조 파악
- **컴포넌트**: `apps/player/src/components/` 하위 파일 목록
- **스토어**: `apps/player/src/stores/` 의 상태 구조 (Zustand)
- **훅**: `apps/player/src/hooks/` 의 주요 훅 목록

#### 1-4. apps/storyteller 분석

- **라우트**: `apps/storyteller/app/` 하위 파일 목록
- **컴포넌트**: `apps/storyteller/src/components/` 하위 파일 목록
- **스토어**: `apps/storyteller/src/stores/` 의 상태 구조
- **훅**: `apps/storyteller/src/hooks/` 의 주요 훅 목록

#### 1-5. packages/shared 분석

- **타입**: `packages/shared/src/types.ts`에서 export되는 주요 타입
- **이벤트**: `packages/shared/src/events.ts`에서 정의된 소켓 이벤트 인터페이스
- **역할**: `packages/shared/src/roles.ts`에서 정의된 역할 목록, 밤 행동, 배분 알고리즘

#### 1-6. 설정 파일 분석

- `biome.json`: 린팅/포매팅 주요 규칙
- 루트 `tsconfig.json`: 프로젝트 레퍼런스

#### 1-7. 스킬 목록

- `.agents/skills/` 하위 디렉토리별 SKILL.md의 name과 description 수집

### 2. 현재 문서 읽기

- 기존 `.claude/CLAUDE.md`와 `README.md`를 읽습니다.
- 각 문서의 기존 **구조와 톤**을 유지하면서 내용만 갱신하는 것이 원칙입니다.

### 3. 변경점 도출

수집한 정보와 기존 문서를 비교하여 변경이 필요한 항목을 식별합니다:

- 새로 추가된 컴포넌트, 훅, 스토어, 이벤트, 역할
- 삭제된 항목
- 이름이나 경로가 변경된 항목
- 소켓 이벤트 추가/변경
- 게임 페이즈 변경
- 역할 시스템 변경
- 스크립트 변경

### 4. 결과 출력 및 확인

변경점을 아래 형식으로 출력합니다:

```
## 📋 문서 갱신 대상

### .claude/CLAUDE.md
| # | 섹션 | 변경 유형 | 내용 |
|---|------|-----------|------|
| 1 | 코드베이스 구조 | 추가 | WhisperModal 컴포넌트 경로 추가 |
| 2 | 주요 이벤트 | 수정 | whisper:request 이벤트 페이로드 변경 |

### README.md
| # | 섹션 | 변경 유형 | 내용 |
|---|------|-----------|------|
| 1 | 프로젝트 구조 | 추가 | packages/ui 디렉토리 추가 |
```

변경점이 없으면 "문서가 최신 상태입니다"를 출력하고 종료합니다.

사용자에게 적용 여부를 확인합니다:
- **전체 적용**: 모든 변경사항 반영
- **선택 적용**: 항목별 수락/거부
- **적용 안 함**: 결과만 확인

### 5. 문서 갱신

Edit 도구를 사용하여 각 문서를 수정합니다.

#### .claude/CLAUDE.md 갱신 규칙

- 기존 섹션 구조를 유지합니다 (프로젝트 개요, 코드베이스 구조, 핵심 규칙, 이벤트 흐름, 역할 시스템, 게임 페이즈, 주요 컴포넌트, 개발 시 주의사항 등).
- **코드베이스 구조**: 실제 디렉토리와 파일 경로를 반영합니다.
- **이벤트 흐름**: `events.ts`에 정의된 실제 이벤트와 일치시킵니다.
- **역할 시스템**: `roles.ts`에 정의된 역할, 밤 행동, 피드백 타입을 반영합니다.
- **주요 컴포넌트**: 실제 존재하는 컴포넌트만 나열하고 설명을 최신화합니다.
- **게임 페이즈**: 실제 Phase 타입과 각 페이즈별 동작을 반영합니다.
- 한국어로 작성합니다.

#### README.md 갱신 규칙

- 기존 섹션 구조를 유지합니다 (프로젝트 소개, 기술 스택, 프로젝트 구조, 앱별 설명, 게임 흐름, 역할, 개발, 아키텍처 특징 등).
- **기술 스택**: 실제 사용 중인 라이브러리와 도구를 반영합니다.
- **프로젝트 구조**: 실제 디렉토리 트리와 일치시킵니다.
- **앱별 설명** (`apps/server`, `apps/player`, `apps/storyteller`, `packages/shared`): 실제 기능과 구현 사항을 반영합니다.
- **게임 흐름**: 실제 구현된 게임 플로우와 일치시킵니다.
- **구현된 특수 능력 / 역할**: `roles.ts` 기준으로 반영합니다.
- **개발 섹션**: 실제 스크립트 명령어와 일치시킵니다.
- **아키텍처 특징**: 실제 아키텍처 패턴을 반영합니다.
- 한국어로 작성합니다.

### 6. 검증

갱신된 문서들을 다시 읽어서 아래 사항을 확인합니다:

- 마크다운 문법이 올바른지
- 실제 코드와 불일치하는 내용이 없는지
- 섹션 간 중복 내용이 없는지

문제가 발견되면 즉시 수정합니다.
