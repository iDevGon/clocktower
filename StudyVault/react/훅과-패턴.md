# React 훅과 패턴

## useEffect

- 사이드 이펙트(데이터 페칭, 구독, DOM 조작)를 수행하는 훅
- 의존성 배열로 실행 시점 제어:
  - `useEffect(fn)` — 매 렌더링마다 실행
  - `useEffect(fn, [])` — 마운트 시 1회만 실행
  - `useEffect(fn, [dep1, dep2])` — dep1 또는 dep2 변경 시 실행
- 클린업 함수: effect 함수에서 함수를 반환하면 언마운트 또는 다음 effect 실행 전에 호출
- Strict Mode에서 개발 중 effect가 2번 실행될 수 있음 (의도적)

## useRef

- `.current` 프로퍼티에 변경 가능한 값을 저장하는 컨테이너
- 값 변경이 리렌더링을 트리거하지 않음 (useState와의 핵심 차이)
- DOM 요소 참조: `<input ref={inputRef} />`
- 이전 값 저장, 타이머 ID 저장 등에 활용

## useMemo와 useCallback

- `useMemo(fn, deps)`: 계산 결과를 메모이제이션. deps가 변경될 때만 재계산
- `useCallback(fn, deps)`: 함수 자체를 메모이제이션. deps가 변경될 때만 새 함수 생성
- `useCallback(fn, deps)`는 `useMemo(() => fn, deps)`와 동일
- 과도한 메모이제이션은 오히려 성능 저하 — 실제 병목 지점에만 적용

## useContext

- Context API로 prop drilling 없이 트리 깊숙한 곳에 데이터 전달
- `createContext()` → `Provider`로 값 제공 → `useContext()`로 소비
- Context 값이 변경되면 해당 Context를 구독하는 모든 컴포넌트가 리렌더링
- 자주 변경되는 값은 Context보다 상태 관리 라이브러리(Zustand 등) 사용 권장

## Custom Hooks

- `use`로 시작하는 함수 — 다른 훅을 조합하여 로직 재사용
- 상태 로직을 캡슐화하지만, 상태 자체는 공유하지 않음 (각 호출마다 독립적 상태)
- 관심사 분리에 유용: `useForm()`, `useAuth()`, `useSocket()`

## 훅 규칙

1. **최상위에서만 호출**: 조건문, 반복문, 중첩 함수 안에서 호출 금지
2. **React 함수 컴포넌트 또는 Custom Hook에서만 호출**: 일반 JS 함수에서 호출 금지
3. 이 규칙들은 React가 훅 호출 순서에 의존하여 상태를 관리하기 때문에 필수적

## 일반적인 패턴

### Lifting State Up
- 두 자식 컴포넌트가 같은 데이터를 공유해야 할 때, 공통 부모로 state를 올림

### Controlled vs Uncontrolled
- **Controlled**: React state가 폼 값의 단일 진실 공급원 (`value={state}` + `onChange`)
- **Uncontrolled**: DOM이 값을 관리, `ref`로 접근 (`defaultValue` 사용)

### Composition vs Inheritance
- React는 상속보다 합성(composition)을 권장
- `children` prop이나 render props로 컴포넌트 합성
